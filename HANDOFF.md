# ShortList — Production Handoff & Deployment Guide

This document provides step-by-step instructions for operating, verifying, deploying, and maintaining the ShortList web application.

---

## 1. Quickstart (Local Development)

### Prerequisites
- Python 3.11.x (Strictly Python 3.11)
- Node.js 20+ and npm 10+
- Google Chrome (for automated browser CDP verification)

### Step 1: Clone & Environment Setup
```powershell
# Navigate to repository root
cd C:\dev\AI_screening

# Backend Python virtual environment
py -3.11 -m venv backend\.venv
backend\.venv\Scripts\Activate.ps1
pip install --upgrade pip
pip install -r backend\requirements.txt

# Frontend dependencies
cd frontend
npm ci
npm run build
cd ..
```

### Step 2: Database Initialization & Demo Seeding
```powershell
# Initialize schema via Alembic migrations and seed sample demo data
backend\.venv\Scripts\python scripts\seed.py
```

### Step 3: Start Application Locally
```powershell
# Run backend with integrated frontend SPA serving
backend\.venv\Scripts\python -m uvicorn app.main:app --app-dir backend --host 127.0.0.1 --port 8000 --reload
```
Open `http://127.0.0.1:8000` in your browser.

## 3. Secret Generation (PowerShell)

When deploying to production, generate a cryptographically strong 32+ character `JWT_SECRET`:

```powershell
# Run in PowerShell to generate a secure random 32-byte Base64 key:
[Convert]::ToBase64String((1..32 | ForEach-Object { Get-Random -Minimum 0 -Maximum 256 }))
```

Copy the generated output and configure it as `JWT_SECRET` in your hosting provider's dashboard.

## 4. Managed PostgreSQL Setup (Neon)

ShortList includes a built-in `DATABASE_URL` normalizer in `backend/app/db/url.py` that automatically maps Neon and Render connection strings to `postgresql+asyncpg` with `ssl=require`.

1. Go to [Neon.tech](https://neon.tech) and create a new project.
2. Under **Connection Details**, select **PostgreSQL** and copy the connection string:
   ```text
   postgresql://[user]:[password]@[endpoint].neon.tech/neondb?sslmode=require
   ```
3. Set this URL as the `DATABASE_URL` environment variable. The app automatically sanitizes parameters and runs Alembic migrations on startup.

## 5. Cloud Deployment (Render Blueprint)

ShortList is fully configured for zero-downtime containerized deployment using the included `render.yaml` blueprint.

### Step 1: Connect GitHub Repository on Render
1. Log in to [Render.com](https://render.com).
2. Go to **Blueprints** -> **New Blueprint Instance**.
3. Select your GitHub repository (`ShortList`).
4. Render will parse `render.yaml` and configure the Web Service automatically.

### Step 2: Configure Environment Variables
Configure the following in the Render Dashboard (under **Environment**):

| Environment Variable | Recommended Value | Notes |
| :--- | :--- | :--- |
| `ENV` | `production` | Enforces secure cookies, strict CORS, disables stack traces |
| `JWT_SECRET` | *(Generated random 32+ char key)* | Auto-generated by Render blueprint or via PowerShell |
| `DATABASE_URL` | `postgresql://...` | Connection URI from Neon or Render PostgreSQL |
| `GEMINI_API_KEY` | *(Your Google AI Studio Key)* | Leave blank for deterministic heuristic scoring fallback |
| `SEED_DEMO_DATA` | `true` (first run) / `false` | Seeds demo accounts and 30 sample CVs if DB is empty |
| `CORS_ORIGINS` | *(Leave empty for same-origin)* | Default same-origin protection in production |

### Step 3: Deploy
Click **Apply Changes**. Render will:
1. Multi-stage build the Docker image (`node:20` compiles React/Vite frontend; `python:3.11-slim` sets up backend runtime).
2. Start the non-root container honoring `$PORT`.
3. Perform health checks on `/api/health`.

## 7. Production Troubleshooting Guide

| Issue / Symptom | Probable Cause | Remediation / Fix |
| :--- | :--- | :--- |
| **`MissingGreenlet` error on relationships** | Un-eager loaded relationship accessed across async sessions | Relationships are strictly configured with `lazy="raise_on_sql"` and `lazy="joined"`. Always use `.options(selectinload(...))` for multi-hop relationship queries in services. |
| **`500 Internal Server Error` on startup** | `JWT_SECRET` missing, default dev key, or shorter than 32 characters when `ENV=production` | Generate a 32+ character Base64 secret using PowerShell command and assign to `JWT_SECRET`. |
| **Client queries cross-client requisition** | Identifier enumeration attempt | System automatically returns HTTP `404 Not Found` (never 403 or 500) to protect tenant privacy and obscure requisition ID existence. |
| **`asyncpg` connection failure with Neon** | Neon `sslmode=require` or `channel_binding` incompatible with asyncpg | `app/db/url.py` automatically normalizes `sslmode=require` to `ssl=require` and removes `channel_binding`. Ensure `DATABASE_URL` is passed through `normalize_database_url`. |
| **Missing Google Gemini API Key** | `GEMINI_API_KEY` env var empty | System transparently falls back to deterministic heuristic evaluation mode. The top UI banner reflects "Heuristic Scoring Mode (Deterministic)" and `/api/health` reports `scoring_mode: "heuristic"`. |
| **Candidate data deletion request** | GDPR / DPDP right to erasure | Trigger `DELETE /api/candidates/{id}`. Personal data is permanently redacted in DB, and a hash-only entry is recorded in `AuditLog` without storing PII. |
| **Client cannot see contact details** | Candidate has not been shortlisted | Contact details (email, phone) remain `[MASKED_UNTIL_SHORTLIST]` until client explicitly approves shortlist decision in portal. |
